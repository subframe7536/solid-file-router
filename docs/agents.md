# Agent Guide

This document gives coding agents deterministic entry points for integrating
`solid-file-router` and maintaining this repository. For repository-wide code
style, commands, and collaboration rules, read [AGENTS.md](../AGENTS.md) first.
Do not duplicate those rules here.

## Operating Rules

1. Treat source types and tests as the current truth. Documentation can lag.
2. Do not edit generated route declarations by hand. `src/routes.d.ts` is
   regenerated by the upstream `types` writer (`output` option).
3. Keep `@solidjs/vite-plugin` in the consuming application's Vite config.
   This package does not configure it.
4. Import runtime APIs from `solid-file-router`, plugin APIs from
   `solid-file-router/plugin`, MDX runtime from `solid-file-router/mdx`, and
   the manifest from `virtual:routes` (kept name; overridable via `moduleId`).
5. Enable `solid-file-router/client` types before importing `virtual:routes`.
6. `route`, `router`, `routers`, and `convention` are the seams — prefer
   changing conventions over patching generated output.
7. `convention`, `router`, and `routers` are mutually exclusive plugin
   options.
8. `pagesDir` is resolved against the Vite **root** in the `config` hook —
   `BaseFileSystemRouter` otherwise eagerly resolves `dir` against cwd, and
   upstream calls `router.getRoutes()` from `configEnvironment` before
   `configResolved` runs.
9. This is v1 on the Solid 2 **prerelease** stack — pin upstream versions.

## Consumer Task Map

| Task                 | Required action                                                      | Verify                                                |
| -------------------- | -------------------------------------------------------------------- | ----------------------------------------------------- |
| Install              | Add the package, `solid-js`, `@solidjs/web`, `@solidjs/router`, Vite, `@solidjs/vite-plugin` | Dependency versions satisfy `package.json`            |
| Configure routes     | Register `solid()` and `fileRouter()`                                | Vite starts and `src/routes.d.ts` is generated        |
| Add a page           | `export const route` + `export default` from `.jsx`/`.tsx`           | Generated path appears in route types                 |
| Add a layout         | Add `_layout.tsx` in the ancestor directory                          | Descendants render through it                         |
| Add an app root      | Add optional `src/pages/_app.tsx`                                    | `/(app)` wraps the route tree                         |
| Navigate dynamically | `Router.paths.<route>(params)` from `createFileRouter()`             | Result is a `TypedPath`; call it again for the string |
| Add metadata         | `route.metadata` — rendered through `useHead`                        | `data-dh` tags appear in SSR/client head              |
| Add SSG              | `solid({ start: true, ssr: true })` + `fileRouter({ ssg: {} })` + `src/App.tsx` | Build emits `dist/client/*.html` and `404.html`       |
| Use built-in MDX     | Install Satteri and set `mdx: true`                                  | `.md`/`.mdx` routes are generated and render          |
| Use a CMS/provider   | `routeProviders` with `glob`/`load`                                  | Provider entries appear as `?pick=` virtual modules   |

Use [guide.md](guide.md) for workflows and [reference.md](reference.md) for exact
options and types.

## Minimal Consumer Integration

```text
vite.config.ts       registers solid() and fileRouter()
tsconfig.json        includes solid-file-router/client, jsxImportSource @solidjs/web
src/pages/**/*.tsx   route modules (route export + default component)
src/index.tsx        createFileRouter() + render (SPA)
src/App.tsx          start-mode root (SSR/SSG)
src/routes.d.ts      generated; never hand-edit
```

A valid route module:

```tsx
import { definePage, defineRoute } from 'solid-file-router'

export const route = defineRoute({ info: { title: 'Home' } })
export default definePage(() => <h1>Page</h1>)
```

The scanner checks export presence only — helper calls and arbitrary
expressions in the initializer are fine. Both helpers are identity functions.

## Behavioral Invariants

### Route generation

- `filesystem-routing` scans `pagesDir` for `extensions`
  (`js/jsx/ts/tsx` plus `md/mdx` when `mdx` is enabled).
- `/(app)` is the root group; group segments appear in manifest paths and are
  stripped in route-tree paths.
- Private `_` segments, `components/`, `node_modules`, and `dist` never
  generate pages.
- `404.tsx` maps to `*404`; `[id]` → `:id`; `-[x]`/`[...x]` → `*x` splats.
- `?pick=` narrows module exports — never bypass it for config reads.

### Boundary and config adaptation

- `Errored` fallback receives an `ErrorAccessor` — call `err()` for the error.
- `loadingComponent`/`errorComponent` inherit down the tree; `inherit` blocks.
- `metadata` becomes `useHead` tags registered inside the route component.
- `draft: true` survives dev builds and is filtered in production (with its
  subtree).
- Without an `errorComponent`, errors are logged in development.

### Types

- `virtual:routes` exports the flat manifest (default) and `pageRoutes` tree.
- `Router.paths.<seg>(params)` returns a `TypedPath` node — call it for the
  string, pass search/hash on the terminal call.
- `Router.fileRoutes`/`routeInfo`/`routeMetadata` come from `createFileRouter`.

### SSG

- Requires `solid({ start: true, ssr: true })` (or `ssg.serverEntry` for a
  custom `Request → Response` handler).
- Prerender runs on the **ssr** environment's `closeBundle` (client when no
  ssr env exists).
- `/` → `index.html`, `/x` → `x.html`, `/x/` → `x/index.html`, always `404.html`.
- Preview middleware registers **pre-internal** — misses return `404.html`
  with status 404; dynamic routes are not served.

### MDX

- `jsx: false` + `jsxImportSource`/`providerImportSource` =
  `solid-file-router/mdx` — intrinsic and component elements route through
  `Dynamic` (the only path valid on both client and SSR).
- `$$route` points at `virtual:sfr-mdx-route:<src>` — re-compiles only
  `route`/`frontmatter` exports so the component never lands in the manifest
  chunk.

### Route providers

- Provider modules use non-`\0` virtual ids under
  `node_modules/.sfr-virtual/` — `\0` ids skip Solid compilation.
- Entries land in the router via `_addRoute` + `reload` on the shared
  `BaseFileSystemRouter`.
- Rescans union across all environment routers before removing stale entries.

## Change-to-Test Matrix

| Change                            | Narrow verification                                   |
| --------------------------------- | ----------------------------------------------------- |
| Filename conventions, ignores     | `pnpm test -- tests/convention.test.ts`               |
| Inheritance, metadata, draft      | `pnpm test -- tests/adapter.test.ts`                  |
| SSG paths, filename map, filters  | `pnpm test -- tests/ssg.test.ts`                      |
| MDX module/frontmatter shape      | `pnpm test -- tests/mdx-module.test.ts tests/mdx-frontmatter.test.ts` |
| Plugin/options/pipeline           | `pnpm play:build`                                     |
| SSG end-to-end                    | `pnpm play:ssg:build`                                 |

Required full verification for production changes:

```bash
pnpm typecheck && pnpm test && pnpm lint
pnpm play:build && pnpm play:ssg:build
```

## Documentation Maintenance

Before changing documentation, verify claims in this order:

1. Public types in `src/index.ts`, `src/plugin.ts`, `src/route/adapter.ts`,
   `src/route/convention.ts`, `client.d.ts`
2. Defaults and generated behavior in implementation
3. Expected edge cases in tests
4. Runnable configuration in `playground`
5. Existing prose

Keep the documentation surfaces distinct:

- `README.md`: positioning, installation, shortest working setup, navigation
- `docs/guide.md`: task-oriented consumer workflows
- `docs/reference.md`: complete public behavior and exact defaults
- `docs/ssg.md`: the end-to-end static generation workflow
- `docs/mdx.md`: built-in Markdown/MDX setup and component customization
- `docs/agents.md`: deterministic integration and maintenance instructions
- `MIGRATION.md`: v0.7 → v1 breaking changes

Do not copy a full reference section back into the README. Link to the owning
document and keep one canonical explanation for each behavior.

## Generated and Derived Files

- Consumer `src/routes.d.ts` files are generated by the upstream types writer.
- `playground/src/routes.d.ts` is generated; do not hand-edit.
- `dist/` is build output. Do not use it as the primary source for documentation
  or implementation decisions.
- `virtual:routes` exists only through Vite plugin resolution; its public type
  declaration is `client.d.ts`.

## Handoff Checklist

- The requested behavior is covered without unrelated refactors.
- Public imports and generated shapes remain compatible or the breaking change
  is explicitly documented.
- Relevant narrow tests pass.
- `pnpm typecheck`, `pnpm test`, `pnpm lint` pass when applicable.
- Generated files were changed only through their owning generator.
- Documentation links resolve and examples match current imports and defaults.
