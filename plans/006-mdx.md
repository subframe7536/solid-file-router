# 006 — MDX：编译产物改为 `route` 导出 + 运行时移植到 Solid 2

Written against `d049326`. 依赖 004。产出：`src/mdx/` 适配新模块约定，
删除对 `createRoute` 的依赖。

## 模块形态变化

旧生成产物：

```ts
import { createRoute } from 'solid-file-router'
export default createRoute({ info, metadata, matchFilters, inherit, draft, component: MDXContent })
```

新产物（官方约定，`route` 导出 + 默认组件）：

```ts
export const route = { info, metadata, matchFilters, inherit, draft }
export default MDXContent // 或 extendLoad.mdxContent 包装后的组件
```

`src/mdx/router.ts` 的 `load()` 生成代码相应修改（去掉 `createRoute`
import 与包装），`MdxRouteConfig` 保持 frontmatter 字段不变。

## `toRoute` 处理（关键）

官方 `PageFileSystemRouter.toRoute` 对 `.md`/`.mdx` 特判：只发
`$component pick: ["$css"]`，不发 `$$route`，因此 frontmatter 的
route 配置拿不到。在 `DefaultFileSystemRouter`（002）中覆盖
`toRoute`：

```ts
toRoute(src) {
  if (/\.mdx?$/i.test(src)) {
    return {
      page: true,
      $component: { src, pick: ['default', '$css'] },
      $$route: { src, pick: ['route'] },
      path: this.toPath(src),
    }
  }
  return super.toRoute(src)
}
```

`src?pick=route` 经过 mdx 编译 transform（`order: 'pre'`，id 正则须匹配
`?` query：`/\.(md|mdx)(\?.*)?$/i`——现有 `REG_MARKDOWN_MODULE_ID` 已满足）→
satteri JS → fs tree-shake 收窄到 `route` 导出。

## 编译插件

`createMdxPlugin`（`src/mdx/plugin.ts`）基本保留：

- transform `order: 'pre'`、filter 同现正则；
- `compileMdx` 继续走 satteri `mdxToJs`（`jsx: true`、
  `providerImportSource: 'solid-file-router/mdx'`），但**去掉默认导出包装**
  ——直接输出 `export default MDXContent`（satteri 原生产物即含），并追加
  `export const route = <frontmatter.routeConfig>`（`extendLoad.routeConfig`
  merge 后）与 `export const frontmatter`；
- `extensions` 需加入 `md`、`mdx`（fileRoutes 的 router config），文档要求
  `solid({ extensions: ['.jsx', '.tsx', '.mdx'] })`（satteri 产物已是
  JS/JSX 调用，solid 插件只负责后续 JSX 编译——001#7 验证）。

`extendLoad.mdxContent` 包装逻辑保留（生成包装组件字符串作为新的
default export 名）。

## 运行时移植（`src/mdx/runtime.ts`，Solid 2）

- `mergeProps` → `merge`；`MDXContext.Provider` → 直接
  `createComponent(MDXContext, {...})`（context 即 provider）；
- `Dynamic` 改从 `@solidjs/web` 导入；
- `import type { Component, JSX, ParentProps } from 'solid-js'` 不变；
- `intrinsicComponents`/`MDXProvider`/`useMDXComponents` 逻辑不变；
- `merge` 下 `undefined` 显式覆盖——`useMDXComponents(local)` 合并语义
  确认不受影响（spread 合并同样行为）。

`client.d.ts` 的 `*.md`/`*.mdx` 声明保留（Component/JSX 类型来源
`solid-js`，`frontmatter` 导出保持）。

## `mdxRouteProvider` 出口删除

`mdxRouteProvider` 作为 routeProvider 的形式不再需要——MDX 直接走
`extensions` + `toRoute` 特判。`fileRouter({ mdx: true | MdxOptions })`
选项保留（`filter`/`transformPath`/`extendLoad`/`pagesDir` 语义映射到
router/toPath/编译选项）。

## 验证

`tests/mdx-frontmatter.test.ts` 保留并适配（frontmatter 解析不变）；
新增 `tests/mdx-module.test.ts`：断言 `load()` 产物含
`export const route`、`export default`，无 `createRoute`。

## 边界

- 不升级 satteri 大版本；001#7 若失败则升级/替换（记录）。
- `?pick=` 与 satteri transform 的顺序问题（001#5）若失败，
  备选：`toRoute` 返回 `$$route` 指向由 frontmatter 内联生成的
  虚拟模块。
